# 词间部署与域名配置

本文使用保留示例域名 `words.example.com`，部署时替换为自己的域名。需要能运行 Docker Compose 的 Linux 主机，以及已经安装的 Nginx。先确认 8765 端口空闲、Nginx 包含的配置目录，以及其他站点使用的域名和端口。

## 1. 启动应用

将仓库放到 `/opt/wordgarden`，编辑 `compose.yaml`，设置 `WORD_ORIGIN: "http://words.example.com"`。来源不能带路径，协议、域名与端口必须和实际访问地址一致。本文采用普通 HTTP，不需要证书，也不添加 HTTPS 跳转。

```bash
cd /opt/wordgarden
docker compose -p wordgarden up -d --build
docker compose -p wordgarden ps
curl http://127.0.0.1:8765/api/health
docker compose -p wordgarden exec wordgarden python manage.py create-user learner
```

密码通过终端隐藏输入，长度 12–128 字符。HTTP 公网传输不加密，请设置独立密码。

容器端口只绑定宿主机 `127.0.0.1:8765`，无需在云安全组开放 8765。容器以 UID 10001 运行，数据写入命名卷，应用根目录只读。

## 2. DNS 与 Nginx

在 DNS 控制台增加 A 记录，主机名使用自己的子域名，记录值为服务器公网 IPv4。若存在 AAAA，确保 IPv6 确实指向可访问此站点的主机。

将 `deploy/words.example.com.http.conf` 中的域名替换为真实域名。先使用 `nginx -T` 确认配置包含路径，再复制到该目录。以下假设目录为 `/etc/nginx/conf.d/`：

```bash
cp deploy/words.example.com.http.conf /etc/nginx/conf.d/wordgarden.conf
nginx -t && systemctl reload nginx
curl -H 'Host: words.example.com' http://127.0.0.1/api/health
curl http://words.example.com/api/health
```

健康接口均应返回 `{"status": "ok"}`。云安全组与主机防火墙需要允许外部访问 TCP 80。Nginx 模板通过 `server_name` 分流，不要覆盖其他站点。

手机地址栏明确输入 `http://自己的域名`。如果浏览器使用 HTTPS，而 443 上没有该域名的独立站点，可能进入其他默认站点。此时确认访问协议、浏览器自动 HTTPS 设置及已有 HSTS，再检查对应端口的配置。

## 3. 更新与记录保留

更新前先备份，再执行：

```bash
cd /opt/wordgarden
git pull --ff-only
docker compose -p wordgarden up -d --build
docker compose -p wordgarden logs --tail 60 wordgarden
curl http://127.0.0.1:8765/api/health
```

持续使用 `-p wordgarden`，命名卷会保留数据库。不要执行 `docker compose down -v`，该命令会删除数据卷。

## 4. 在线备份与恢复

使用新文件名在线备份，再复制到容器外：

```bash
docker compose -p wordgarden exec wordgarden python manage.py backup /app/storage/backup-20261017.sqlite3
docker compose -p wordgarden cp wordgarden:/app/storage/backup-20261017.sqlite3 ./backup-20261017.sqlite3
```

备份包含账号和学习记录，应放在私有存储中，不要提交到仓库。建议定期复制到另一台设备。备份文件存在时，管理命令会拒绝覆盖。

恢复时先停止应用，另行备份当前卷，将有效备份恢复为卷内 `wordgarden.sqlite3`，并确保 UID/GID 10001 可读写。旧数据库的 WAL/SHM 旁文件不能与另一份备份混用。恢复后启动应用，核验账号及学习统计。卷路径随 Compose 项目名和环境而异，恢复前应先用 `docker volume inspect` 确认目标。

## 5. 常见问题

| 现象 | 检查方式 |
| --- | --- |
| 页面正常，登录报来源不匹配 | 核对 `WORD_ORIGIN`，修改后执行 `docker compose -p wordgarden up -d --force-recreate wordgarden` |
| Nginx 返回 502 | 先查 `docker compose -p wordgarden ps` 和容器日志，再测回环健康接口 |
| 进入另一网站 | 分别检查 80 / 443 的 `server_name`、实际协议和 DNS A / AAAA |
| 容器报源码 Permission denied | 重新构建当前 Dockerfile，检查构建时普通用户的导入权限检查 |
| Cookie 无法保持 | 确认 `WORD_ORIGIN` 与浏览器协议一致，HTTP 来源不应配置为 HTTPS |

可选 HTTPS 模板为 `deploy/words.example.com.https.conf`，使用前需准备证书、确认续期机制，并同步调整 `WORD_ORIGIN`。不要在没有证书和对应站点的情况下启用模板。
